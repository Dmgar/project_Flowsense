## Product experience

- Use the supplied FlowSense brandbook and original logo artwork as the visual authority. Choose legible variants for light and dark surfaces, preserve the artwork and improve contrast throughout the interface.
- On initial entry, prominently ask whether a new visitor wants a guide. Offer clear choices to start the guide or explore independently, and keep a persistent way to reopen the tutorial.
- Provide an interactive tutorial with a dark backdrop and a visible spotlight on the real control or area being explained. Explain the available functions in approachable steps, with forward, backward, skip and close actions.
- Refine the entire frontend: visual hierarchy, spacing, typography, navigation, cards, page layouts, empty states, loading and unavailable states, transitions, microinteractions and engaging details that help people understand the product.
- Improve desktop, tablet and mobile layouts, keyboard access, readable labels, touch targets, focus behavior and reduced-motion support as part of implementation.
- Keep all product interface copy, code and repository documentation in English; communicate with the user in Spanish.

## Working instructions

- Do not run or add tests, functional test workflows, database checks, lint, type-checking commands or production builds until the user explicitly requests verification. Do not substitute browser acceptance testing for the suspended checks. The existing development preview may remain available for the user and for design work.
- Use the user's computer, browser and relevant tools when they help the design work. Research visual references, information or tutorials when useful. This permission does not authorize unrelated account, system, publishing or communication actions.
- Preserve existing routes, evidence provenance, camera playback behavior, saved user preferences, API contracts and existing legal/consent interfaces. Keep this phase within frontend code; do not change databases or backend services to pursue visual improvements.
- Keep illustrative scenarios clearly distinguished from observations. Describe unavailable backend data honestly and do not invent measurements or imply that playback or data operations were verified.
- Report implemented changes separately from verification. Leave verification pending until requested and do not describe untested changes as validated.
